# BankOps — Banking Operations Request Management Platform

A low-code portfolio project designed to centralize banking operations requests, improve request tracking, and reduce manual follow-up through automated email notifications and dashboard reporting.

## Project Overview

BankOps simulates an internal banking operations workflow where employees can submit requests, track their status, and manage assignments. The platform provides role-based interfaces and reporting dashboards to improve visibility into request progress.

## Problem Statement

Managing operational requests without a centralized system can make it difficult to track assignments, monitor status changes, and follow up on pending requests.

## Solution

BankOps provides a centralized platform for request submission, assignment, status management, attachment handling, and operational reporting. Automated email notifications inform assigned users when requests are assigned to them.

## Technologies Used

- **Microsoft Power Apps** — Canvas application and user interface.
- **Microsoft Dataverse** — Data storage for requests, users, and request updates.
- **Microsoft Power Automate** — Automated email notifications for assigned requests.
- **Microsoft Power BI** — Dashboard reporting and visualization of request data.

## Key Features

- Role-based interfaces for Employee, Manager, and Admin.
- Request submission and tracking.
- Four request statuses: Open, In Progress, Completed, and Canceled.
- Request assignment and attachment handling.
- Automated assignment email notifications.
- KPI dashboards for monitoring request volumes and status distribution.

## Project Statistics

- **50+** simulated requests used for testing and demonstration.
- **3** user roles.
- **4** request statuses.
- Automated email flow tested successfully, with email delivery verified.

*All requests and user records are simulated demonstration data, not real banking data.*

## Project Scope and Limitations

BankOps is a portfolio demonstration built with Microsoft Power Platform. The data is simulated, and the application is not connected to a production banking environment. SQL and SharePoint are not part of the current implemented solution.
